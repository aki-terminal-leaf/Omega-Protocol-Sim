## 3. AnAn 依賴分類

**AnAn 目前是唯一已確認的完整安裝及 Windows／遊戲驗證環境，不代表技術上永遠只能用這台。**

| 類別 | 工作 | 現在可否不等 AnAn | 解除依賴的條件／替代方式 |
| --- | --- | --- | --- |
| 可立即獨立 | 資料 schema、清單／版本／雜湊設計、已保存素材盤點、格式研究、純資料測試 | 可以 | 不需要完整遊戲即可定義與驗證接口；未實作的備份流程仍是待辦，不冒稱已執行 |
| 可立即獨立 | 標記模式、Bot 依當下實際標記反應、配置 UI／保存／報告／重試 | 可以 | 先用已核對打法；不猜未確認的區服規則，不讀隱藏答案 |
| 可立即獨立 | 機制狀態機、碰撞／接觸／同時事件框架、HP／死亡等戰鬥框架 | 可以 | 參數與真實行為校準須另取證，框架完成不等於遊戲一致 |
| 可立即獨立 | 已有 AVFX 的時間軸／粒子／曲線／生命週期／重置開發、Linux 真實渲染測試 | 可以，有限範圍 | 有來源樣本的功能可以推進；未知欄位明示 unsupported，不先假定完整 shader／binder 語義 |
| 一次性資料依賴 | 整套 SqPack、缺失 shader／材質／動畫／綁點／場景原檔 | 目前仍需 AnAn，除非另一完整副本可用 | 一次完整、驗證過的備份後，按需抽取不再經過 AnAn |
| 工具相容性依賴 | 既有模型／材質 exporter 與 Havok 動作採樣 | 目前不能把 Windows 管線視為已移植 | 拆開 SqPack 純讀取與 TexTools／SharpDX；驗證 Linux 可用鏈。Windows-only DLL 可先由獨立 Windows worker 轉成中性樣本；Wine／替代 decoder 僅列候選，通過實測才算移除依賴 |
| 實機參考依賴 | 原版效果觸發／停止、骨點與動畫姿勢、顏色／透明度／深度／隨機行為 | 已保存基準可離線比；不足時需遊戲環境 | 先一次保存可重播基準與必要觀察；新未知項仍須 AnAn 或另一可執行 FFXIV 的環境。套件與 shader 不能自動替代執行語義 |
| 行為證據依賴 | 接線門檻、感染／同時事件順序、精確快照、傷害曲線 | 有合適公開／已存紀錄的項目可獨立；其餘需補證 | 可重現錄影／紀錄，必要時可控實機對照；AnAn 僅是其中一個取得環境，不把所有校準都綁死在它 |

| 非 AnAn 專屬問題 | Web 啟動／瀏覽器／WebGL2／輸入／匯出驗收 | 可以另行診斷 | 使用有界、不同方法的乾淨環境或可用瀏覽器交叉驗證；現有新舊包同卡不作通過依據，不盲重試相同 harness |

DirectX shader 二進位不能直接當 Godot shader 載入。保存完整 SHPK 後，仍需
分析材質語義、轉譯／重建 Godot 相容實作及逐項畫面驗證；備份不等於這項工程已完成。

## 4. 尚未完成的功能範圍

### A. 離線素材基礎設施

1. 來源版本與容量盤點、唯讀／可續傳備份流程、完整性驗證、可重現工具鎖檔。
2. 原始包 → 已知路徑索引 → 按需抽取 → 中性格式 → Godot 的可重現鏈。
3. 依 AVFX／模型／時間軸／場景做遞迴相依盤點，列出每個缺失／無法解析的引用。
   區分未定位路徑、原包不存在、解析器不支援及已驗證無需的引用，不靜默忽略。
4. 將 Windows-only 轉換器與遊戲原檔讀取解耦；已轉樣本與 raw 檔都保留來源雜湊。

### B. AVFX／原版視覺

1. Timeline／scheduler 的 trigger、loop、stop、unlock、fade、clip、reset 與 target scope。
2. Emitter 的體積／速度／繼承／小數生成數及原始隨機分布；particle 的 polyline、decal、
   billboard、velocity 等尚未支援類型。
3. 多層貼圖 TC2–4、normal／palette／reflection／distortion／screen-copy、
   Fresnel、lighting、blend／depth／cull／UV 及角色骨架 binder／socket。
4. 場地 phase layer、原版霧／光照／發光／轉場、技能姿態與動畫時間軸。
5. 定位真實頭頂標記與場地邊界效果；保留現有重建版 fallback，不以 UI 素材冒稱已定位。
6. 通過代表效果驗證後才接入正式練習：先 P3 左右充能、流星／彗星等已保存樣本，
   再逐批擴到 TOP 各機制。**TOP 所需功能覆蓋**與**全遊戲所有 AVFX 格式通吃**分開列，
   後者不是備份後自然達成，也不給未經驗證的固定工期承諾。

### C. 攻略、標記與 Bot

- 基礎手動 17 標、配置保存／拖放／重綁已存在，不重寫。
- 補完整手動／輔助／不使用模式，報告與通過條件區分模式。
- 每個打法連結可核對的上標訊號／時間、分工、清除時點與建議場地配置。
- Bot 依當下實際標記反應；漏標／錯標／晚標不能被隱藏正解修正。
- 補區服未確認分支與時間路徑，保留來源／推導／訓練值標籤；不是湊滿 100 格。

## 6. AnAn 下一次可用時的集中採集包

1. **不開遊戲即可取得**：讀取實際安裝位置、版本、各 SqPack 檔案容量及時間戳；
   在未更新中的穩定安裝做唯讀複製，保留全部索引／資料檔及工具版本。
   若傳輸前後版本／檔案改變，該快照拒絕驗收；不把混合版本當完整備份。
2. **優先小包**：先抽 TOP 尚缺 shader／材質／綁點／技能 PAP／TMB 與遞迴引用，
   保存 raw bytes、來源虛擬路徑與輸出 SHA256；完整備份另續傳。
3. **需要實際遊戲畫面的部分**：效果起／停／命中／淡出、骨點隨動、場地各相位；
   記錄效果／技能／姿勢／時間基準、鏡頭、解析度與視覺設定。手動 overhead 資源仍要辨識，
   不以已有 UI 圖替代。需用外掛或額外軟體的觀察方式另行評估，不默默安裝。
4. **判定樣本**：優先補接線／感染／同時事件／射程邊緣等現有缺口，含失敗反例；
   可從現有合法紀錄解答的項目不重做實機。保存可分享的正規化事件，不公開原始私人紀錄。
5. **保存中性輸出**：利用既有可用 Windows DLL 一次轉出優先技能的骨架／動作樣本，
   同時保留原 PAP／SKLB 與工具雜湊；這可解除日常使用依賴，但不等於轉換器已跨平台。

取得資料後，斷開 AnAn 再做 P2 驗收。單純「複製成功」不足以宣稱離線作業成功。

## 7. 儲存規劃與備份驗證

下面仍是容量預算，**沒有 AnAn 全安裝目錄實測總量**。原始包不全量預轉 PNG／WAV／GLB。

| 項目 | 規劃值 |
| --- | --- |
| 一個版本完整原始備份 | 約 130–150 GiB，待實際盤點 |
| 工具、已知路徑索引與按需匯出 | 約 30–60 GiB |
| 更新／傳輸暫存 | 約 15–30 GiB，依實際策略控制 |
| 可用空間目標 | 保留餘裕後建議 250–300 GiB 可用；多版本可規劃 500 GiB 等級，非本次採購決定 |

本次 VPS Volume 為 200 GiB 級，`df -h` 顯示約 163 GiB 可用（前次細讀約 162 GiB）。
目前資料已占約 27 GiB，不能把總容量當可用容量。原包也許裝得下，但未證明工作餘裕足夠。
300 GiB 總容量是先前建議的起點，不等同 300 GiB 可用；擴容涉及費用，本次不執行。
先取實際容量再決定，不以估值承諾一定放得下。

建議資料層分離：`source/<version>` 原始唯讀快照、`catalog` 路徑／引用／雜湊、
`derived/<tool-version>` 可再生轉換、`reference` 影像／事件基準、`exports` 候選包。
不改現有路徑／symlink；大量資料用已驗證可用於頻繁存取的 Volume，
延遲敏感活動 DB 才另按負載處理。寫入前驗證掛載，避免落到根碟。

傳輸採可續傳檔案／受控區塊與單一 staging，不同時保留多份全量壓縮／解壓副本。
以雙端檔案數／總 bytes／逐檔 SHA256／版本一致性驗收，再從多資料片抽樣讀取。
快照命名只在驗證完成後轉為 accepted；工具／安裝更新不得原地改寫已驗證 raw 快照。
這是此規劃待實作的流程，不代表已完成備份或新排程。

VPS 一份副本能解除 AnAn 的素材存取依賴，但不等於跨故障域的多副本災難備援。
不把備份登入憑證、帳號設定或不相關個資列入素材取得需求。

## 8. 完成判準與研究風險

- **完整素材備份**：實際版本／清單完整、雜湊一致、可讀，且所有資料片的索引與資料檔齊備。
- **TOP 材料齊備**：所有已定位 TOP 依賴有 raw 檔及來源；未定位／未解析清單不能隱藏。
- **離線日常開發成立**：不接 AnAn 可新增抽取／轉換／載入代表新資源、跑測試及 Linux 渲染；
  Windows 專屬工具未替代的部分另外明示。
- **原版精度通過**：逐項原版資料／時序／像素／行為來源可追查；隨機效果使用可比基準或分布，
  不要求無意義的逐像素完全一致，也不因畫面無錯誤就視為相同。
- **發行通過**：新平台實際匯出包驗收完成，原生／headless 證據分列，才更新版本及展示。

通用 AVFX、完整原始隨機規則、Windows Havok 相容化與伺服器判定校準屬研究性工作。
先用代表案例建立可行性與效能門檻，再排後續批次；目前不給假精確的總工期或完成百分比。

## 9. 既有方案預檢與參考

- 先沿用本專案 `tools/export_official_*`、`avfx_*` 與既有中性 GLB／JSON 管線，
  不另造 SqPack 容器解析器。[Lumina](https://github.com/NotAdam/Lumina) 是優先純資料讀取候選；
  現有 exporter 還載入 TexTools／SharpDX，不能因 .NET 支援 Linux 就宣告整條鏈相容。
- [VFXEditor](https://github.com/0ceal0t/Dalamud-VFXEditor) 已有 AVFX／PAP／TMB／EID／
  SHPK／MTRL 等格式研究；其 in-game 播放不提供可直接嵌入 Godot 的獨立原版引擎。
  專案先前解析研究釘 `05f6eb0cce19a6a91ae275bce609299d573914b3`，更新前需核對差異。
- [Atlas](https://github.com/Enceladeum/Atlas) 可作抽取／結構參考，但仍需要本機 SqPack；
  舊 AVFXTools 不足以視為完整現代播放器。未發現並驗證可直接替代目前目標的完整方案。
- 素材、private reference 與第三方 DLL 不收入公開 source commit；僅提交原創程式、
  來源描述、合成測試與必要的文字清單。

本計畫是下一步工作與依賴的可審核清單，不是已完成各項功能的宣告。
