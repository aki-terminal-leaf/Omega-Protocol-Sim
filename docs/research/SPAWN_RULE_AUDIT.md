# 20 項機制：物件生成條件核對（2026-10-22）

這次追查 `Encounter.build()` 實際呼叫的生成器、runtime 產生的物件與
`stage_entities`，不把舊 fixture 或攻略建議站位當成實際敵人物件位置。
**結論：v0.3.8 並非全部符合；已修正 Sigma 塔向連動與 LB 的兩項位置問題。**
本表核對有限、可證實的生成條件，不是全部伺服器 RNG／機率／出生幀的認證。

## 三項修正

1. **Sigma 塔向**：原本 M、塔陣各自八方亂數；正常生成現在只有
   `塔陣尖端／缺口方向 = M 方向 或 M+180°`。不是自由八方、也不是與 M 無關。
   Elemental 原文的 “oriented either to where Omega-M was standing before, or
   directly opposite” 與四份原始紀錄一致。額外強制旋轉只保留在程式壓力測試，
   標為 `forced_training`，不是正常練習的副本配置。
2. **LB 女本體**：受保護的女本體在真北約 `(0,-10)`，不是舊顯示的 `(0,-22)`。
   四份紀錄以真正本體 NPC15712 的資源位置核對，未使用假人／玩家站位代替。
3. **LB 五個場外分身的聯合配置**：原先獨立抽箭、盾，並假設 Flare 是盾+120°，
   會混出沒有來源支持的配置，甚至箭、盾重疊。正常生成改為四份已驗證的
   **完整五物件配置抽一份**，保留男／女連線源、箭、盾、Flare 的相對關係。
   這是保守的已觀測子集，**不是聲稱副本只有四種配置**；額外廣範圍測試 API
   仍明確標為 `forced_training_superset`，不進正常隨機池。

沒有更改傷害時間、尺寸、移速、0.5 秒傷害範圍提示或既有種子／R 重練規則。
種子到配置的映射會隨本次生成器修正改變；同一新版內重練仍確定一致。
